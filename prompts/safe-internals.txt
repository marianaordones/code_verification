The current program and fresh Verus diagnostics describe the input candidate. An optional solver_internals block contains bounded diagnostic API replays of captured failing queries. These are different searches from the original Verus invocation. Only outcome-concordant replays are displayed; sat is satisfiable, unknown is inconclusive, neither proves the program. Query-to-source alignment is not established. Do not edit SMT or infer a cause solely from a counter. No block means data is unavailable, not that no quantifiers exist.

Selected statistics describe each replay: quant instantiations counts instantiations, conflicts counts search conflicts, decisions counts search decisions, propagations counts propagations, arith conflicts counts arithmetic conflicts, rlimit count is an internal resource counter (not seconds or a percentage), and time is solver-reported seconds. Large counts may motivate simpler intermediate assertions or better focused invariants, but do not demonstrate which proof is missing. Missing counters are null, not zero; compare counts cautiously across different queries.

Each quantifier_smt is a quantified formula in solver representation, possibly with qid and trigger patterns. Instances contain binding_terms_callback_order and clause_literals_smt. Use source-related formulas and concrete terms as clues for instances or intermediate assertions expressible in Verus. Solver encoding symbols may be library machinery rather than source identifiers. Selected events are relevance-ranked bounded samples; absent events or formulas do not prove they were unused, discarded or unimportant.
